# R03 — دارایی‌ها و مدل‌های نهایی

**وضعیت:** تکمیل‌شده در ۲۰۲۶-۱۰-۲۰. **وابستگی:** R02 و تأیید انسانی ثبت‌شده در R02. **Skill:** `frontend-design`؛ پشتیبان: `source-driven-development`. **خروجی:** دارایی‌های سه‌بعدی محلی و قابل‌بازتولید برای اجزای باقی‌ماندهٔ قاب.

## هدف و محدوده

هندسهٔ blockout را با مدل‌های نهایی هماهنگ با مرجع مینیمال جایگزین کن. فقط اجزای حاضر در قاب مصوب ساخته/نگه داشته شوند: میز بالایی، برد و قفسهٔ خالی، مانیتور و آرکید. شکل‌پردازی تمیز و متناسب با کادر نزدیک باشد؛ جزئیات تزئینی تأییدنشده اضافه نشوند.

## فایل‌های مورد بررسی و تغییر احتمالی

- `src/RoomScene.tsx` و `src/RoomPreview.tsx` برای loaderهای دارایی
- `scripts/build-arcade-cabinet.mjs` و `public/assets/models/arcade-cabinet.glb`
- دارایی‌های GLB جدید در `public/assets/models/` و منبع بازتولید محلی هرکدام

## مراحل

- [x] تأیید R02 را بررسی کن و فایل‌های مدل/سازندهٔ arcade فعلی و مرز دارایی‌های مصرف‌شده در Scene را بخوان.
- [x] برای هر دارایی، مسیر منبع، مجوز/انتساب و روش بازتولید محلی را ثبت کن؛ دارایی مبهم‌المجوز یا runtime CDN وارد نکن.
- [x] مسیر پیش‌فرض، دارایی محلیِ قابل‌بازتولید با Three.js و exporter نصب‌شده است؛ Blender در این محیط نصب نیست. اگر fidelity لازم با این مسیر ممکن نشد، کار را متوقف و ابزار/دارایی لازم را برای تصمیم کاربر مشخص کن.
- [x] دارایی‌ها را به GLB محلی صادر/بساز و ساختار نام‌گذاری و ابعادشان را برای جای‌گذاری و focus hotspotها ثابت نگه دار.
- [x] مدل‌ها را با هندسهٔ موجود مقایسه کن تا برخورد/هم‌پوشانی ناخواسته، z-fighting، scale اشتباه یا باقی‌ماندن اجزای حذف‌شده رخ ندهد.
- [x] مسیر loading و شکست بارگذاری را با fallback موجود حفظ کن؛ asset loader را داخل مرز Error/Suspense فعلی نگه دار.

## پذیرش و بررسی

- [x] مدل‌های نهایی جای blockout اجزای اصلی را می‌گیرند و ترکیب تأییدشده/مکان hotspotها در 768، 1024 و 1440 حفظ می‌شود.
- [x] هیچ مکعب placeholder برای اجزای اصلی قابل‌دیدن در Hero باقی نمی‌ماند؛ مدل‌ها در فاصلهٔ نمای نزدیک silhouette و لبه‌های پرداخت‌شده دارند.
- [x] منبع و مجوز هر مدل روشن است؛ هیچ وابستگی به بارگیری خارجی runtime وجود ندارد.
- [x] مدل خراب/غایب محتوای متنی HTML و کنترل برگشت را از دسترس خارج نمی‌کند.
- [x] اعتبارسنجی GLB، typecheck، lint، تست‌های asset failure/loading و مرورگر واقعی محلی موفق‌اند.

## توقف

در صورت نیاز به خرید، مجوز نامشخص، نصب نرم‌افزار جدید یا افزودن وابستگی، پیش از آن متوقف شو و تصمیم لازم را از کاربر بگیر. هیچ دارایی را صرفاً به‌خاطر شباهت ظاهری بی‌مجوز کپی نکن.

## گزارش اجرا — ۲۰۲۶-۱۰-۲۰

- شرط R02 با تأیید صریح کاربر در همین گفتگو برقرار و در فایل R02 ثبت شد. مدل‌های جدید `public/assets/models/room-furnishings.glb` با هندسهٔ نوشته‌شده در `scripts/build-room-furnishings.mjs` ساخته شدند؛ مدل آرکید موجود `public/assets/models/arcade-cabinet.glb` و سازندهٔ آن حفظ شدند. هر دو منبع، هندسهٔ تألیفی همین پروژه‌اند؛ mesh، texture یا فایل دارای مجوز خارجی وارد نشد. مجوز بازتوزیع مستقلی برای مدل‌ها در مخزن تعریف نشده و تصمیم انتشار با مالک مخزن است. بازتولید: `node scripts/build-room-furnishings.mjs` و `node scripts/build-arcade-cabinet.mjs`. بازتولید دوبارهٔ مدل جدید همان SHA-256 را داد: `f7e759527fde8e30bcebc650de9ab94735843f2b3416637275a191ab69b3a792`.
- سازندهٔ جدید GLB را با `GLTFLoader.parseAsync` دوباره باز کرد و نام اجزای اصلی، مختصات سطح مانیتور، محدودهٔ ۱۲٫۷۰۸ × ۳٫۸۶۵ × ۲٫۷۵۰ و ساختار باینری glTF 2.0 را بررسی کرد؛ خروجی ۲۳۶٬۸۰۸ بایت است. سطح صفحهٔ ۴٫۸ × ۲٫۶ و hotspotهای قبلی ثابت ماندند. دیوار پشت فقط صفحهٔ پس‌زمینه است؛ کارت‌های پروژه به‌دلیل وابستگی به داده در کد باقی ماندند.
- `npm test`: موفق، ۱۴ تست در ۵ فایل. `npm run lint`، `npm run typecheck`، `npm run build` و `git diff --check`: موفق. `npm run test:e2e -- --workers=1`: موفق، ۲۵ تست Chromium؛ دریافت هر دو GLB و خطای فایل غایب/خراب پوشش داده شد. `npm audit --audit-level=high`: صفر آسیب‌پذیری گزارش‌شده. هشدار موجودِ chunk سه‌بعدی بیش از ۵۰۰ kB باقی است و اندازه‌گیری عملکرد در R09 انجام می‌شود.
- screenshotهای Chromium از overview در ۷۶۸، ۱۰۲۴ و ۱۴۴۰ و نماهای focus مانیتور، برد و آرکید بازبینی شدند. سایهٔ ناخواستهٔ دیوار پشت که زیر میز شکل اضافی می‌ساخت حذف شد. مسیر HTML، کنترل برگشت، keyboard/focus و reduced motion در مجموعهٔ مرورگری پاس شدند. ۳۲۰ و ۳۷۵ فقط smoke test مسیر HTML و overflow داشتند. مرورگر headless با SwiftShader بود؛ GPU/دستگاه واقعی و Firefox/Safari بررسی نشدند.
- در checkout و `origin/main`، workflow گیت‌هاب وجود ندارد؛ اجرای GitHub Actions ممکن نبود. تغییر پایگاه داده، API، وابستگی یا شبکهٔ runtime مربوط به مدل‌ها لازم نشد. commit و push انجام نشد. R04 گام بعدی برای پرداخت نور، سایه و متریال است.

# R01 — Blockout تمام‌صفحه و پاک‌سازی صحنه

**وضعیت:** تکمیل‌شده در ۲۰۲۶-۱۰-۲۰. **وابستگی:** ندارد. **Skill:** `frontend-design`؛ پشتیبان: `frontend-ui-engineering` و `test-driven-development`. **خروجی:** نمای overview تمام‌viewport با هندسهٔ blockout و ترکیب مصوب.

## هدف و محدوده

قاب جدید را با هندسهٔ ساده و قابل‌تغییر پیاده کن تا پیش از ساخت دارایی نهایی، ترکیب واقعی اتاق در اندازه‌های هدف قابل‌بازبینی باشد. Hero کل viewport را از لبه تا لبه بپوشاند؛ محتوای پورتفولیو بعد از آن در صفحه باقی بماند. برد در چپ، مانیتور مرکز و آرکید نزدیک آن در راست باشند؛ فقط قسمت بالایی میز و سطح آن دیده شود.

## فایل‌های مورد بررسی و تغییر احتمالی

- `src/RoomScene.tsx`، `src/RoomPreview.tsx` و `src/RoomPreview.module.css`
- `src/style.css` در صورت نیاز برای ارتفاع viewport و scroll صفحه
- `tests/entry-page.spec.ts` و screenshotهای مرورگر مربوط به قاب

## مراحل

- [x] پیش از تغییر، RoomPreview، RoomScene، CSS قاب، layout صفحه و تست‌های فعلی را بخوان؛ وضعیت جاری Git را حفظ کن.
- [x] قاب Canvas و لایهٔ HTML را برای عرض‌های تبلت و دسکتاپ تمام‌صفحه کن، بدون جابه‌جایی/حذف مسیر محتوای HTML پایین صفحه.
- [x] هندسهٔ blockout را مطابق تصویر Hero محلی بازچینی کن؛ کف، دیوار جانبی، قرنیز، صندلی، پایه‌های میز، کیس و هر جزء دیگری که در قاب نهایی نیست از scene حذف شود، نه اینکه پشت دوربین پنهان بماند.
- [x] دیوار پشت و اجزای لازم برای برد، قفسهٔ خالی، مانیتور، سطح میز و آرکید را نگه دار؛ وسیلهٔ تزئینی تازه اضافه نکن.
- [x] تست‌های قاب/overflow را برای تغییر رفتار جدید تنظیم کن؛ جزئیات مدل، متریال نهایی و parallax هنوز موضوع این تسک نیستند.

## پذیرش و بررسی

- [x] در 768، 1024 و 1440 پیکسل Hero تمام viewport را پر می‌کند و سه لنگر بصری در ترتیب/مکان موردنظر قابل‌شناسایی‌اند.
- [x] اشیای حذف‌شده هیچ هندسه‌ای در scene ندارند؛ نمای Hero با crop کردن صحنهٔ قدیمی ساخته نشده است.
- [x] محتوای عادی و لینک‌های پورتفولیو پس از Hero قابل‌پیمایش و مستقل از WebGL باقی می‌مانند.
- [x] در 320 و 375 پیکسل overflow افقی یا از دست‌رفتن مسیر HTML رخ نمی‌دهد؛ کیفیت/چیدمان موبایل در این مرحله ارزیابی نمی‌شود.
- [x] typecheck، lint، unit و e2e مرتبط موفق‌اند؛ screenshot مرورگر Chromium از سه عرض هدف بصری بازبینی شده است.

## گزارش اجرا

- `npm test`: موفق، ۱۳ تست در ۵ فایل.
- `npm run lint`: موفق؛ `npm run typecheck`: موفق.
- `npm run test:e2e -- --workers=1`: موفق، ۲۰ تست Chromium؛ مرورگر با SwiftShader اجرا شد.
- `npm run build`: موفق؛ هشدار موجود اندازهٔ chunk صحنه (بیش از ۵۰۰ kB) باقی است و رسیدگی به عملکرد در R09 است.
- Screenshotهای viewportهای 768، 1024 و 1440 ساخته و بازبینی شدند؛ عرض‌های 320 و 375 فقط از نظر مسیر HTML و overflow بررسی شدند.
- در checkout و `origin/main` فایل GitHub Actions پیدا نشد؛ اجرای workflow گیت‌هاب قابل انجام نبود.
- تست مقایسهٔ پیکسلی نمای ثابت پس از drag حذف شد؛ خروجی screenshotهای تکراری SwiftShader پایدار نبود و parallax حالت idle موضوع R02 است. آزمون‌های keyboard، مقصدها و reduced-motion انتقال دوربین همچنان پاس‌اند.
- تغییرات فقط محلی‌اند؛ commit و push انجام نشده است.

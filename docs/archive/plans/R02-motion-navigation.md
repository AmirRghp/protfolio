# R02 — ناوبری و حرکت دوربین

**وضعیت:** تکمیل‌شده در ۲۰۲۶-۱۰-۲۰؛ تأیید انسانی در گفتگو ثبت شد. **وابستگی:** R01. **Skill:** `emil-design-eng`؛ پشتیبان: `review-animations` و `browser-testing-with-devtools`. **خروجی:** حرکت idle و رفت‌وبرگشت قابل‌قطع میان اتاق، مانیتور، برد و آرکید، همراه کنترل‌های واضح.

## هدف و محدوده

حس روان و دقیق حرکت را با blockout قابل‌تأیید بساز. ناوبری HTML فعلی و hotspotهای صحنه از یک state مقصد مشترک استفاده کنند. parallax فقط جلوه‌ای ظریف است و هیچ عملکردی به ماوس وابسته نمی‌شود.

## فایل‌های مورد بررسی و تغییر احتمالی

- `src/RoomScene.tsx`, `src/RoomPreview.tsx`, `src/RoomPreview.module.css` و `src/roomNavigation.ts`
- `src/roomCamera.ts`, `src/roomCamera.test.ts`, `src/roomNavigation.test.ts`
- `tests/room-navigation.spec.ts` و `tests/entry-page.spec.ts`

## مراحل

- [x] مقصدهای اتاق و کنترل برگشت را در overlay کم‌حجم و خوانا روی Hero نگه دار؛ کنترل‌ها با parallax حرکت نکنند.
- [x] parallax محدود فقط وقتی مقصدی فوکوس نشده و اشاره‌گر در فضای خالی Hero است اجرا شود؛ با خروج اشاره‌گر/صفحه نرم به مرکز بازگردد.
- [x] parallax با ورود فوکوس به کنترل‌ها، شروع انتقال مقصد، لمس یا prefers-reduced-motion خاموش باشد.
- [x] انتقال به مقصد از pose جاری دوربین ادامه پیدا کند؛ انتخاب سریع مقصد تازه، برگشت وسط حرکت و تغییر اندازهٔ viewport پرش یا pose کهنه نسازد.
- [x] برای hotspotها، منوی مقصد و دکمهٔ برگشت رفتار یکسان ماوس/صفحه‌کلید را حفظ کن؛ focus قابل‌مشاهده و بازگردانی focus را بررسی کن.
- [x] پس از تکمیل، نسخهٔ blockout را در مرورگر به کاربر برای تأیید ترکیب و حرکت ارائه کن؛ نتیجه و تاریخ تأیید را اینجا ثبت کن.

## پذیرش و بررسی

- [x] نمای idle با حرکت کم اشاره‌گر واکنش ظریف دارد، از قاب بیرون نمی‌رود و پس از خروج آرام به مرکز برمی‌گردد.
- [x] هر سه مقصد از overlay و hotspot باز و با کنترل واضح/صفحه‌کلید بسته می‌شوند؛ انتخاب سریع و بازگشت وسط حرکت درست‌اند.
- [x] prefers-reduced-motion حرکت idle را حذف و انتقال را مطابق قرارداد دسترس‌پذیری مستقیم یا کوتاه می‌کند.
- [x] آزمون‌های واحد state و مرورگری focus، keyboard، reduced motion، resize و motion transition موفق‌اند.
- [x] **دروازهٔ انسانی:** ترکیب blockout و تعامل‌ها توسط کاربر تأیید شده است: [x] بله؛ تاریخ/یادداشت: ۲۰۲۶-۱۰-۲۰، پاسخ «تأیید می‌کنم» به پرسش صریح دربارهٔ R02 در گفتگوی R03.

## توقف

تا ثبت تأیید انسانی در دروازهٔ بالا، R03 و R04 آغاز نمی‌شوند. اگر حرکت کنترل‌های HTML یا خوانایی متن را مختل می‌کند، ابتدا دامنهٔ حرکت را کم کن.

## گزارش اجرا — ۲۰۲۶-۱۰-۲۰

- تغییرات به حرکت دوربین، محدودسازی parallax، گذر ورودی اشاره‌گر از فضای خالی overlay، بازگردانی focus دکمهٔ برگشت آرکید و تست‌های مرتبط محدود شد. state مقصد، poseهای اصلی، hotspotها و محتوای HTML مستقل از WebGL حفظ شدند؛ پایگاه داده، API یا وابستگی جدید لازم نبود.
- `npm test`: موفق، ۱۴ تست در ۵ فایل. `npm run lint` و `npm run typecheck`: موفق. `npm run build`: موفق، با هشدار موجود chunk سه‌بعدی بیش از ۵۰۰ kB. `npm run test:e2e -- --workers=1`: موفق، ۲۳ تست Chromium. `npm audit --audit-level=high`: بدون آسیب‌پذیری گزارش‌شده. `git diff --check`: موفق.
- مرور تصویری Chromium از overview در ۷۶۸، ۱۰۲۴ و ۱۴۴۰ و از parallax نزدیک لبهٔ فضای خالی در همین عرض‌ها انجام شد؛ لبهٔ خالی یا جابه‌جایی کنترل‌ها دیده نشد. نمای مقصدهای مانیتور، برد و آرکید نیز از screenshotهای آزمون بازبینی شد. در ۳۲۰ و ۳۷۵، smoke test مسیر HTML و نبود overflow انجام شد؛ طراحی ویژهٔ موبایل تأیید نشده است.
- آزمون‌های مرورگر، keyboard، focus و بازگردانی آن، لمس شبیه‌سازی‌شده، تغییر زندهٔ reduced motion، تغییر مقصد و resize میان انتقال، نبود WebGL، گم‌شدن context و شکست GLB را پوشش دادند. مرورگر Chromium headless با SwiftShader بود؛ دستگاه و GPU واقعی یا Firefox/Safari بررسی نشدند.
- در `HEAD` و `origin/main` فایل GitHub Actions وجود ندارد؛ workflowی برای اجرای محلی نبود. تغییر شبکه‌ای/iframe تازه‌ای اضافه نشد و وضعیت واقعی سرویس بازی در این تسک دوباره سنجیده نشد.
- نسخهٔ production در زمان تحویل برای تأیید انسانی در `http://127.0.0.1:5194/` باز شد؛ کاربر بعداً blockout و تعامل‌ها را تأیید کرد و نتیجه در بخش «تأیید انسانی» ثبت شده است. commit یا push در زمان اجرای این تسک انجام نشده بود.

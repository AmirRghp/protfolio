# پورتفولیوی سه‌بعدی Amirreza Gholipour

یک پورتفولیوی انگلیسی با نمای آغازین ثابت اتاق، حرکت ظریف اشاره‌گر و ناوبری میان مقصدهای سه‌بعدی. با فوکوس روی مانیتور، یک دسکتاپ HTML با نوار وضعیت زنده روی سطح واقعی نمایشگر curved باز می‌شود و پنجرهٔ باز آن بین overview و مانیتور حفظ می‌شود. تنظیم کاهش حرکت سیستم، حرکت اشاره‌گر را خاموش می‌کند. محتوای HTML بدون WebGL هم قابل‌خواندن است.

## پیش‌نیازها

- Node.js شاخهٔ `22` از نسخهٔ `22.12` به بعد، یا شاخهٔ `24` یا `26`؛ مطابق `package.json`
- npm همراه Node.js

## راه‌اندازی محلی

```sh
npm ci
npm run dev
```

نشانی توسعه را Vite در ترمینال نمایش می‌دهد. برای بررسی نسخهٔ production:

```sh
npm run build
npm run preview
```

## فرمان‌های بررسی

```sh
npm run typecheck
npm run lint
npm test -- --run
npm run build
npm run test:e2e
```

آزمون مرورگر با Playwright و Chromium اجرا می‌شود. `npm run test:e2e` ابتدا build تولیدی می‌سازد و سپس صفحه‌ها و تعاملات را روی آن بررسی می‌کند.

## به‌روزرسانی محتوا

محتوای مالک، سوابق کاری و پروژه‌ها در `src/content.ts` قرار دارد. متن رابط پورتفولیو انگلیسی است.

- سوابق کاری را با شرکت، عنوان و بازهٔ زمانی واقعی و قابل‌تأیید ثبت کنید.
- برای پروژه‌ها `id` یکتای پایدار، عنوان، توضیح کوتاه، نشانی GitHub معتبر و `icon` (نام گلیف: `chat`، `layers` یا `radar`) وارد کنید. قالب کارت مشترک است و افزودن پروژه به منطق جداگانهٔ صحنه نیاز ندارد.
- `websiteUrl` اختیاری است: نشانی اپ دسکتاپ ابتدا از آن خوانده می‌شود و در نبود آن به `githubUrl` همان پروژه برمی‌گردد. `highlights` اختیاری است و چیپ‌های کوتاه اپ را می‌سازد.
- برای تغییر متن‌ها و لینک‌ها، `npm run typecheck`، `npm run lint`، `npm test -- --run` و `npm run test:e2e` را اجرا کنید.
- اطلاعات تماس یا فایل رزومه را فقط وقتی وارد کنید که منبع واقعی آن‌ها موجود و تأیید شده باشد.

## صحنه و دارایی‌ها

- `public/assets/models/arcade-cabinet.glb` مدل کابینت آرکید است؛ اسکریپت ساخت آن `scripts/build-arcade-cabinet.mjs` است.
- `public/assets/models/curved-monitor.glb` مدل مانیتور میز است؛ اسکریپت آماده‌سازی آن `scripts/prepare-curved-monitor.mjs` است و منبع، مجوز و تغییرات در `public/assets/models/ATTRIBUTION.md` ثبت شده‌اند.
- تصویر مرجع طراحی اتاق در اسناد محلی نگهداری می‌شود و در Git نیست؛ این تصویر مدل سه‌بعدی یا مدرک رفتار برنامه محسوب نمی‌شود.
- صحنه به‌صورت chunk جداگانه بارگیری می‌شود. اگر WebGL یا بارگیری صحنه/مدل شکست بخورد، محتوای HTML و کنترل‌های پورتفولیو باید همچنان در دسترس بمانند.

## دسکتاپ مانیتور

- `src/MonitorDesktop.tsx` پوستهٔ دسکتاپ داخل نمایشگر است: wallpaper، نوار وضعیت زنده، ستون آیکون، اسکلت پنجره و جابه‌جایی آیکون‌ها. فهرست اپ‌های دسکتاپ در `src/desktopApps.tsx` جمع می‌شود؛ فایل `about-me.txt` در R06 و اپ هر پروژه در R07 به همین فهرست اضافه شدند.
- `src/AboutMeApp.tsx` محتوای فایل `about-me.txt` است: نام، نقش و سوابق کاری از `src/content.ts` خوانده می‌شود و در یک سطح کاغذی روشن داخل همان پنجرهٔ مشترک نمایش داده می‌شود.
- `src/ProjectApp.tsx` محتوای اپ هر پروژه است: نشانی پروژه در نوار آدرس، خلاصهٔ پروژه و لینک مستقیم. نمایش درون پنجره فقط با دکمهٔ «Load inside this window» آغاز می‌شود و اگر سایت نمایش درون قاب را مسدود کند یا بارگذاری نشود، پیام خطا با لینک مستقیم نمایش داده می‌شود.
- فایل `about-me.txt` با double click باز می‌شود؛ `Enter` روی آیکون همان کار را می‌کند. یک کلیک یا ضربهٔ تنها فقط فوکوس می‌گیرد و آیکون راهنمای «Double-click, double tap, or press Enter to open» دارد.
- آیکون‌های دسکتاپ با ماوس یا لمس در محدودهٔ صفحهٔ مانیتور کشیده می‌شوند و در مرزهای دسکتاپ محدود می‌مانند؛ یک drag واقعی بازشدن اپ را فعال نمی‌کند و پس از تغییر اندازهٔ صفحه هم جای آیکون‌ها دوباره محدود می‌شود.
- `src/GradientWaves.tsx` پس‌زمینهٔ موج‌دار دسکتاپ است؛ پورتی از کامپوننت React Bits با notice در `THIRD_PARTY_NOTICES.md`. در نبود WebGL2 زمینهٔ تیرهٔ CSS زیر canvas باقی می‌ماند.
- `src/monitorProjection.ts` سطح واقعی صفحهٔ مانیتور را از مدل می‌خواند و آن را به مختصات کانواس نگاشت می‌کند؛ `src/RoomScene.tsx` این نگاشت را هر فریم روی لایهٔ HTML می‌نویسد. تغییر این فایل‌ها باید هم‌ترازی دسکتاپ با صفحهٔ فیزیکی را حفظ کند.
- ساعت نوار وضعیت از زمان محلی بازدیدکننده می‌آید و در نیمه‌شب محلی روز و تاریخ را عوض می‌کند؛ قالب زمان در `src/desktopStatus.ts` است.

## مقصدها و مسیر دسترس‌پذیر

- `src/RoomPreview.tsx` مالک state پنجرهٔ باز دسکتاپ است. پنجره با رفتن به overview بسته نمی‌شود؛ اما انتخاب برد یا آرکید، یا شکست صحنه، آن را می‌بندد. بنابراین هر مقصد فقط UI متعلق به خودش را نشان می‌دهد.
- لایهٔ دسکتاپ بیرون از focus مانیتور `inert` است. بازگشت از مانیتور، برد یا آرکید با کنترل HTML «Back to room» ممکن است و focus پس از بستن هر مقصد به همان دکمهٔ مقصد برمی‌گردد.
- `Escape` ابتدا پنجرهٔ باز مانیتور را می‌بندد و focus را به آیکون آغازگر برمی‌گرداند؛ `Escape` بعدی به overview برمی‌گردد. برد و آرکید کنترل بستن/خروج مستقل و قابل‌مشاهده دارند.
- آرکید تا انتخاب «Play game» هیچ درخواستی به سرویس بیرونی نمی‌فرستد. تا زمانی که iframe نمایش داده می‌شود، لینک مستقیم PS1FUN، دکمهٔ «Exit game» و راهنمای خنثیِ «If the game does not appear…» همیشه بیرون قاب می‌مانند. اگر رویداد load تا ۸ ثانیه نرسد، iframe با پیام `role="status"` جایگزین می‌شود؛ این پیام فقط نبود load را گزارش می‌کند. focus پس از Play روی Exit و پس از Exit روی Play می‌نشیند.
- با خطای WebGL، شکست chunk/مدل یا از‌دست‌رفتن graphics context، پنجرهٔ دسکتاپ بسته و لایهٔ آن inert می‌شود؛ focus به کنترل مقصد Monitor و محتوای HTML پورتفولیو منتقل می‌شود.

## محدودیت‌های شناخته‌شده

- build یک هشدار Vite برای chunk سه‌بعدی بزرگ‌تر از ۵۰۰ kB دارد؛ در اندازه‌گیری B12 حجم chunk برابر `966.69 kB` و فشردهٔ gzip برابر `257.95 kB` بود. این اندازه به‌تنهایی زمان بارگیری یا کارایی دستگاه را تعیین نمی‌کند.
- اندازه‌گیری مرورگر B12 روی Chromium headless با SwiftShader نرم‌افزاری انجام شد؛ عملکرد GPU واقعی، دستگاه واقعی و مرورگرهای Firefox/Safari از آن نتیجه‌گیری نمی‌شوند.
- بازی Crash Bandicoot از سرویس بیرونی PS1FUN در iframe نمایش داده می‌شود و لینک مستقیم نیز ارائه می‌شود. شرایط حقوقی سرویس تأیید نشده و بارگیری زندهٔ بازی در محیط آزمون این مخزن تضمین‌شده نیست. ROM یا emulator جداگانه در این پروژه توزیع نمی‌شود. fallback فقط نبود رویداد load در ۸ ثانیه را تشخیص می‌دهد. `load` برای محتوای cross-origin می‌تواند مربوط به صفحهٔ خطای خود مرورگر هم باشد؛ بنابراین نه نشانهٔ موفقیت بازی است و نه شکست شبکه یا `X-Frame-Options` را در والد قابل‌تشخیص می‌کند. به همین دلیل راهنمای خنثی و لینک مستقیم بیرون قاب همیشه قابل‌استفاده می‌مانند.
- اگر پنجرهٔ اپ پروژه در مانیتور باز باشد و بازدیدکننده به overview برگردد، پنجره و iframe بارگذاری‌شده تا انتخاب برد/آرکید یا شکست صحنه باقی می‌مانند. هزینهٔ این iframe در R09 بررسی می‌شود.
- لینک‌های پروژه به مخزن‌های عمومی GitHub می‌روند؛ محتوای خود آن مخزن‌ها خارج از این پروژه نگهداری می‌شود.
- جابه‌جایی آیکون‌های دسکتاپ فقط با drag انجام می‌شود: نه روشی با pointer و بدون drag وجود دارد و نه معادل صفحه‌کلیدی. بنابراین این قابلیت با WCAG 2.5.7 (Dragging Movements) و 2.1.1 (Keyboard) منطبق نیست و R07 از نظر دسترس‌پذیری کامل تلقی نمی‌شود. افزودن روش جایگزین یک تصمیم محصول جداگانه است.
- سایتی که نمایش درون قاب را با `X-Frame-Options` مسدود کند از سمت والد قابل تشخیص نیست؛ در آن حالت مرورگر صفحهٔ خطای خودش را در قاب نشان می‌دهد و لینک مستقیم بیرون قاب همیشه در دسترس است.

جزئیات تصمیم‌ها، وضعیت تسک‌ها و شواهد بررسی در `docs/plans.md` ثبت می‌شود.
